ВОЗВРАТ КЛИЕНТОВ ВЕТКЛИНИКИ И ГРУМИНГА НА ПРИВИВКИ И ПРОЦЕДУРЫ В ОДИН КЛИК: TELEGRAM-БОТ, N8N, POSTGRESQL И OLLAMA (DOCKER COMPOSE, CLOUDFLARE TUNNEL)
Эпизод 49. Канал: @ByteAutomate_AI

ЧТО ЭТО
Каждое утро n8n находит в PostgreSQL питомцев, которым пора на прививку или процедуру через 14 дней, локальная нейросеть Ollama пишет тёплое сообщение с кличкой, Telegram-бот присылает три свободных окна, клиент записывается одной кнопкой. Бот пишет только тем, кто сам дал согласие и номер через QR на стойке ресепшена. Без абонентской платы за сервис: платите за сервер.

В АРХИВЕ
- docker-compose.yml: PostgreSQL 16, n8n, Ollama, cloudflared (Cloudflare Tunnel); тома pg_data, n8n_data, ollama_data, backups;
- .env.example: пример настроек (пароль базы, ключ шифрования n8n, домен, токен туннеля, токен бота, чат администратора, модель Ollama);
- init.sql: таблицы owners (телефон E.164, согласие), pets (защита от дублей), recall_schedule, free_slots, appointments, send_queue, owners_import и функции normalize_phone_e164, import_owners;
- vetclinic_recall_n8n.json: сценарий n8n (41 узел; идентификаторы подключений пустые): согласие по QR, ежедневная выборка за 14 дней, текст Ollama, антиспам-очередь, запись по кнопке, ночное обслуживание и выгрузка журнала;
- backup.sh: резервная копия (дамп PostgreSQL и настройки);
- Инструкция.txt: этот файл.

ВАЖНО ДО ЗАПУСКА (честные ограничения)
1. Автор стек и сценарий на живом сервере и в живом n8n не запускал. Теги образов (n8n, Ollama, cloudflared указаны как latest), узлы Telegram, Postgres, записи файла, HTTP-запросов, формат ошибок и кнопки в вашей версии n8n сверьте с официальной документацией. После первого успешного запуска закрепите версии образов.
2. Первое сообщение Telegram-бота. Бот не может первым написать человеку, который не нажал Start (ограничение Telegram, проверьте по документации Bot API). Поэтому клиентов нельзя «залить» из старой базы в рассылку: каждый должен сам открыть бота. На стойке ресепшена разместите QR-код со ссылкой t.me/ИМЯ_БОТА?start=reception и пояснение, зачем он нужен.
3. Согласие и 152-ФЗ. Номер телефона, кличка и история прививок это персональные данные. Текст согласия, способ его получения, хранение, срок хранения, право на отзыв (команда /stop), условия рассылки проверьте у юриста. Это не юридическая консультация; набор не даёт юридических гарантий. В сценарии текст согласия примерный: замените его своим.
4. Ollama работает локально: данные не отправляются в чужие облака. Модель в .env (qwen2.5:3b) пример, не проверялась: подберите по железу, проверьте качество русского текста и читайте результат перед массовой рассылкой. Нужны память и процессор под модель.
5. Антиспам: сообщения идут через очередь (до 5 в минуту, растущая пауза между клиентами); это снижает риск блокировок, но не отменяет правил Telegram и согласия клиента.
6. Тип и дозировку прививок бот не определяет: даты ставит клиника в recall_schedule. Сообщение не заменяет консультацию врача.
7. Сумма потерь 110 000 ₽ в месяц, 2 500 карточек, срок 14 дней и цена внедрения 45-70 тыс. ₽ в ролике это сценарные примеры и оценки владельца, не замеры.
8. Бесплатный Cloudflare Tunnel: условия и лимиты проверяйте на сайте Cloudflare на момент настройки.
9. Резервная копия обязательна (см. чек-лист ниже).

ШАГ 1. СЕРВЕР
Нужен VPS с Linux, Docker и Docker Compose, достаточный для выбранной модели Ollama. Аренда: Timeweb Cloud по партнёрской ссылке https://timeweb.cloud/r/nf413716
ПОМЕТКА О ВОЗНАГРАЖДЕНИИ: ссылка партнёрская, автор канала получает вознаграждение, цена для вас от этого не растёт. Тарифы (по данным автора на момент записи от ~490 ₽ в месяц, не проверено) и бонус проверяйте на сайте.

ШАГ 2. ТУННЕЛЬ И БОТ
Создайте туннель в Cloudflare Zero Trust, маршрут вашего домена на http://n8n:5678, скопируйте токен в TUNNEL_TOKEN. В Telegram создайте бота у @BotFather, сохраните токен (TELEGRAM_BOT_TOKEN). Свой chat_id для уведомлений администратору узнайте у любого бота-определителя и впишите в ADMIN_CHAT_ID.

ШАГ 3. НАСТРОЙКИ
Скопируйте файлы на сервер, например в /opt/vetclinic. В папке:
  cp .env.example .env
  openssl rand -hex 32     (выполните дважды: для POSTGRES_PASSWORD и N8N_ENCRYPTION_KEY)
Впишите значения, домен HOST, токены, название клиники и модель. N8N_ENCRYPTION_KEY задайте один раз и никогда не меняйте.

ШАГ 4. ЗАПУСК
  docker compose up -d
  docker compose ps
  docker compose exec ollama ollama pull qwen2.5:3b     (или модель из OLLAMA_MODEL)
Должны работать postgres, ollama, n8n и cloudflared. Если контейнер не стартует, смотрите docker compose logs. Откройте https://ВАШ_ДОМЕН и создайте администратора n8n.

ШАГ 5. СЦЕНАРИЙ
В n8n: Workflows, Import from file, vetclinic_recall_n8n.json. Создайте учётные данные Telegram (токен бота) и PostgreSQL (хост postgres, база и пользователь из .env) и выберите их в узлах. Активируйте сценарий (бот должен получать обновления через webhook на вашем домене).

ШАГ 6. ДАННЫЕ И QR
Импорт вашей базы (пример, данные вымышленные):
  INSERT INTO owners_import (raw_phone, owner_name, pet_name, species) VALUES ('8 (999) 000-00-00', 'Анна', 'Рекс', 'собака'), ('+7 999 000 00 00', 'Анна', 'Рекс', 'собака');
  SELECT import_owners();
Две записи с одним номером в разных форматах склеятся в одну карточку. Даты прививок:
  INSERT INTO recall_schedule (pet_id, procedure, due_date) SELECT id, 'комплексная прививка', current_date + 14 FROM pets WHERE name = 'Рекс';
Свободные окна (заполняет клиника):
  INSERT INTO free_slots (slot_start) VALUES (now() + interval '2 days'), (now() + interval '2 days 90 minutes'), (now() + interval '3 days');
Согласие даёт сам клиент: он открывает бота по QR (t.me/ИМЯ_БОТА?start=reception), нажимает Start и «Поделиться номером и согласиться»; сценарий находит карточку по номеру и записывает opt_in_status = opted_in. Без этого рассылка ему не уходит. Для QR используйте любой генератор, который работает без отправки ваших данных в чужие сервисы.

ШАГ 7. ПРОВЕРКА
Выполните шаги 6 на тестовых данных со своим номером телефона, подождите утреннего запуска или временно запустите ветку вручную, нажмите кнопку окна в боте. Проверьте: запись в appointments, повторное нажатие (должно быть отклонено), команду /stop, номер в другом формате, окно, занятое другим клиентом, и ответ при заблокированном боте.

РЕЗЕРВНАЯ КОПИЯ (ЧЕК-ЛИСТ, правило 3-2-1)
[ ] запустить bash backup.sh: дамп PostgreSQL и архив настроек;
[ ] 3 копии, 2 разных носителя, 1 вне сервера, копии зашифрованы (в базе номера и клички);
[ ] ночная выгрузка журнала записей в том backups работает, но она не заменяет полную копию;
[ ] не удалять оригиналы, пока копия не проверена;
[ ] восстановить копию на тестовой машине и открыть расписание и согласия.
